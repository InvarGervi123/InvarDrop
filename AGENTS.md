# Repository Instructions

## Mandatory language policy

- Use English for all authored repository content: source code, comments,
  documentation, README files, security policies, GitHub configuration, workflows,
  and user-facing application text.
- Write all new commit messages, pull request titles/descriptions, issue text,
  review comments, release notes, and other project-authored GitHub content in
  natural, professional English.
- Russian is allowed only in conversational explanations and progress reports
  printed in the Codex terminal. Never copy those reports into repository files
  or GitHub content.
- Do not translate or rename technical identifiers, protocol constants, filenames,
  or user data whose values must remain unchanged. Preserve multilingual fixture
  values; Unicode escapes may represent them in source without changing the
  runtime strings. Supporting arbitrary valid Unicode user data remains required.
- Before committing, inspect changed content for non-English prose and remove
  obsolete language labels. Preserve technical meaning, security requirements,
  protocol versions, resource limits, links, and accurately scoped test results.

## Existing work and delivery boundaries

- Preserve existing uncommitted work and continue the current implementation.
- Run checks appropriate to the changes and report their actual results.
- Follow the user's branch, merge, and release instructions. Do not merge a
  milestone or create a release without the required user authorization.
